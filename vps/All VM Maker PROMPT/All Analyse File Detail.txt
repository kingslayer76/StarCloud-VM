## 2. Project ka sach — StarCloud kya hai

### 2.1 Ek line mein
**StarCloud** ek web panel hai jisse **admin** (aap) KVM par VPS aur VDS banata hai. Customer ko credentials (login details) **Discord** ke zariye milte hain. Order, ticket aur payment bhi Discord par hote hain.

### 2.2 Kaam kaise hota hai (step by step)

1. **Admin setup**: aap website par login karte hain (default `admin/admin`, jise pehli baar login ke baad badalna hai).
2. **Settings**: aap website ke Settings page par Discord bot token dalte hain. Bot apne aap kaam shuru karta hai (ticket, UPI payment ticket, credentials).
3. **Customer Discord par aata hai**: wo ticket kholta hai, plan chunta hai.
4. **Payment**: Discord ticket mein UPI details dikhte hain. Customer payment karta hai, aur admin confirm karta hai. **Website par koi payment gateway nahi hai.**
5. **VPS banana**: admin website par VPS/VDS create form bharta hai (naam, CPU, RAM, disk, password, nested KVM on/off).
6. **Credentials**: VM ban jaane par bot Discord par customer ko credentials bhejta hai.
7. **Customer use karta hai**: wo SSH (ya sshx link) se apne VPS ko chalata hai.
8. **Webhook (optional)**: admin chahe to Discord webhook URL daale. Khali ho to kuch nahi jaata.

### 2.3 Ye cheezein StarCloud mein NAHI hongi
- Windows RDP, Windows templates.
- tmate.
- "Custom price per order" aur "Order record" (order table). Discord ticket hi record hai.
- Website par UPI upload ya payment gateway.

### 2.4 Website kiske liye hai
- **Admin**: poori website. VPS banana, settings, coupons, audit log, maintenance.
- **Customer**: website ka customer hissa **kam priority** par hai. Login ke baad apna VPS start/stop kar sakta hai (AI ke through bhi, confirmation ke saath).

### 2.5 Deadline
User ne pehle 21–22 October 2026 bataya tha, aur flexible bola tha. Aaj 2026-10-25 hai, yaani ye deadline nikal chuki hai. Ye bat user ke saath clearly honest hona zaroori hai.

## 5. Part 2 — Base project: HKVM (`Analyse-File/(Nissalop22)hkvm-2.zip`)

### 5.1 HKVM kya hai
HKVM ek **Node.js web panel** hai jo **QEMU/KVM** VM ko browser se manage karta hai. StarCloud isi ka naya naam hai. Zip ke andar `Hkvm/` folder hai, aur `package.json` ke hisaab se naam `hkvm-panel-free`, version `2.0.0-free`, license **MIT** hai.

### 5.2 Ye kaise bana hai (tech stack, saral bhasha mein)
- **Express**: web server jo pages aur API deta hai.
- **EJS**: HTML templates (views) jo data bharkar page banate hain.
- **sqlite3**: database jo ek file (`data/hkvm.db`) mein rehta hai.
- **express-session**: login session yaad rakhna.
- **bcryptjs**: password ko hash (ulta, wapas na ho sakne wala code) mein save karna.
- **passport + passport-discord**: "Discord se login".
- **ssh2**: browser se VM ke terminal tak SSH connection.
- **ws**: WebSocket, live serial console ke liye.
- **axios**: dusri API ko call karne ke liye.
- **uuid, cors, dotenv**: chhote helper tools.

### 5.3 Folder structure (zip ke andar)
- `app.js` (4,912 lines): poora backend. Ek hi file mein sab kuch (monolith). Ye bahut badi file hai, isliye bugs dhoondhna mushkil hai.
- `licenses.js`: license ka **no-op stub** (kuch nahi karta). Matlab koi license server nahi, koi key nahi.
- `views/`: admin, users, partials, `license_activation.ejs`.
- `public/`: CSS aur images.
- `data/`: database file. Zip mein `hkvm.db` hai (asli data, copy nahi karna).
- `.env`: zip mein hai (secrets ho sakte hain, copy nahi karna).
- `node_modules/`: 239 packages (zip ka size bada isi se hai).

**Ye repo se match**: StarCloud repo ka `app.js` HKVM ke `app.js` se sirf naam badalne ke farq ke saath same hai (normalize karne par sirf 4 lines alag). Yani repo abhi base copy hai, koi naya feature nahi.

#### A1. KVM capability detection (KVM ki jaanch)

#### B4. Public IPv4 aur har VM ko alag port (single shared IP) — PTERODACTYL SAMAJH KE SAATH
Ye feature sabse important hai, isliye detail mein.

**B4.1 Problem kya hai**
- Ek public IPv4 address (jaise `203.0.113.10`) ek hi hai. Lekin 10 VM chahiye.
- Har VM ko port 22 (SSH) chahiye. Lekin ek hi IP par port 22 sirf ek VM ke paas ja sakta hai.
- Isliye har VM ko **alag public port** dena padega, aur ek port ko do VM ko nahi dena.

**B4.2 Hamara solution (Network Address Translation + Port Forwarding)**
- Host machine par ek public IP. Host par port forwarding rule: `public port 20001` → `VM1 ka private IP:22`.
- VM2: `public port 20002` → `VM2 ka private IP:22`.
- Ye router jaisa hai: ghar mein ek public IP, andar kai devices, har device ka alag darwaza.
- HKVM mein ye pehle se hai, lekin **sirf NAT SSH port** (default 2222). Automatic allocation nahi hai.

**B4.3 Pterodactyl ka case (detail mein)**
Pterodactyl ek game server panel hai. Ismein do hisse hote hain:
1. **Panel**: web interface, jo aam taur par port **80** (HTTP) aur **443** (HTTPS) par chalta hai.
2. **Wings**: ek daemon (agent) jo game containers chalata hai. Iska API default port **8080** hai, aur SFTP (file transfer) port **2022**.
3. **Game allocations**: har game server ko ek alag port chahiye, jaise Minecraft ke liye `25565`, aur doosre games ke liye alag.

Ab ek shared IP par 3 VM mein Pterodactyl chalana hai, to problem ye hai:
- VM1 ka Panel port 80 chahega. VM2 ka Panel bhi 80 chahega. Ek hi IP par do VM port 80 nahi le sakte.
- Wings 8080 bhi har VM ko chahiye. Conflict.
- SFTP 2022 bhi conflict.
- Game port `25565` bhi har VM ke Minecraft server ko chahiye. Conflict.

**Solution (teen layer)**:
- **Layer 1 — Website (HTTP/HTTPS)**: ek reverse proxy (jaise Caddy) host par port 80/443 par baitha hai. Ye domain name se decide karta hai ki request kis VM ko jaaye. Jaise:
  - `panel1.example.com` → VM1 ka `:80`
  - `panel2.example.com` → VM2 ka `:80`
  - HTTPS ka certificate Let's Encrypt se apne aap aata hai (kyunki proxy port 80 aur 443 sambhalta hai). Let's Encrypt ko port 80 par pahunchna zaroori hai, isliye domain ka DNS sahi hona chahiye.
- **Layer 2 — Wings aur SFTP (TCP)**: har VM ka port unique rakhna. Port forwarding ke saath:
  - VM1 Wings: public `28001` → VM1 `8080`
  - VM1 SFTP: public `22001` → VM1 `2022`
  - VM2 Wings: public `28002` → VM2 `8080`
  - VM2 SFTP: public `22002` → VM2 `2022`
- **Layer 3 — Game ports (TCP/UDP)**: har game allocation ko ek unique public port. Jaise:
  - VM1 Minecraft: public `30001` → VM1 `25565`
  - VM2 Minecraft: public `30002` → VM2 `25565`
  - Game ports HTTP proxy se nahi chal sakte (ye raw TCP ya UDP hain). Isliye har game ke liye direct forwarding chahiye.

**B4.4 Automatic port allocation (admin ko manual kuch nahi karna)**
- Pool ranges (example): SSH `20000–20999`, Wings/API `28000–28999`, SFTP `22000–22999`, game `30000–39999`.
- Algorithm:
  1. VM banate waqt us VM ki zaroorat list karo (SSH, Wings, SFTP, game ports).
  2. `port_allocations` table mein dekho: kaun se port free hain.
  3. Deny list mein wale port skip karo.
  4. Lowest free port lo, `UNIQUE(public_port, protocol)` constraint ke saath save karo.
  5. Ye transaction mein karo, taaki do VM ko same port na mile.
  6. VM delete hone par ports free karo.
- **Deny list** (kabhi public nahi): jaise MySQL `3306`, PostgreSQL `5432`, MongoDB `27017`, Redis `6379`, Docker API `2375`/`2376`, Elasticsearch `9200`. Inhe public IP par khulne se data chori ka khatra hai.
- **Source**: HVM-8 mein tables `port_allocations`, `port_forwards`, `port_quota`, bulk routes (`/admin/ports/bulk`). Ye verified hai. Pool logic in-house hai.

**B4.5 IPv4 ke 4 modes (master spec)**
| Mode | Kya hai | Kab |
|---|---|---|
| A — NAT + port forward | Ek IP, har VM ko port. (Hamara default, D-9.) | Jab IP kam hain. |
| B — Dedicated bridged IPv4 | Har VM ka apna public IP (bridge). | Jab har VM ko alag IP chahiye aur IP available hain. |
| C — Routed subnet ya 1:1 NAT | Ek subnet ke IP ek-ek VM ko. | Jab provider subnet deta hai. |
| D — IPv6 | Naya address, bahut zyada addresses. | Future ke liye. |

**B4.6 Admin IP Pool page**: IP list, assign aur release, conflict check. Ye apanel ke `public_ips.html` ka idea hai (docs mein zikr, zip ab nahi).

**B4.7 Risk aur honest note**
- Pterodactyl ke Wings ko "behind proxy" mode mein chalana padta hai jab proxy HTTPS sambhalta ho. Ye untested hai, kyunki sandbox mein Pterodactyl install nahi hua.
- Game server ka asli test real VM aur real domain par hi hoga.

- **Status**: 🔵 design hai, code nahi.
- **StarCloud mein kaise jodein**: `services/ports.js` (allocator), `port_allocations` table, Caddy config generator, VM create form mein "needed ports" checklist.

## 10. Part 7 — Badi files (30 MB aur usse upar) upload karne ka tarika

### 10.1 GitHub ki limits (official docs se)
| Tarika | Limit | 30 MB file | Kya karein |
|---|---|---|---|
| GitHub website par drag-drop (browser) | **25 MiB** per file | ❌ fail | Chhoti file hi |
| `git` command line se push | **50 MiB par warning**, **100 MiB par block** | ✅ chal jayegi (warning aa sakti hai) | Repo mein rakhna ho to ye |
| Git LFS (Large File Storage) | Per file: Free/Pro **2 GB**, Team **4 GB** | ✅ | 100 MiB se upar, repo mein rakhna ho to |
| GitHub Release asset | Per file **2 GB** | ✅ | Download ke liye, repo ke bahar |

Sources: GitHub Docs "About large files on GitHub" aur "About Git Large File Storage", aur Stack Overflow / community pages (sab ek hi number dete hain).

### 10.2 Aapke sawal ka seedha jawab
- **30 MB file ko website se upload nahi hoga** (limit 25 MiB).
- **Git command line se 30 MB push ho jayegi**, bas 50 MiB ki warning aa sakti hai. Ye aapke apne computer par karna hoga.
- **100 MB se badi file ke liye Git LFS** ya **Release** use karo.
- **Sabse aasaan**: Google Drive par folder banao, sab files wahan upload karo, phir folder ka link ya naam mujhe do. Main Google Drive connector se list karke padh sakta hoon.

### 10.3 Git command line se 30 MB file upload (step by step, aapke computer par)
1. Git install karo (Windows par "Git for Windows").
2. Repo clone karo:
   `git clone https://github.com/kingslayer76/All-vm-panel.git`
3. Apni branch par jao:
   `cd All-vm-panel`
   `git checkout arena/f1ba8616-all-vm-panel`
4. File ko `Analyse-File/` folder mein copy karo.
5. Stage karo:
   `git add "Analyse-File/aapki-file.zip"`
6. Commit karo:
   `git commit -m "Add Analyse-File: aapki-file.zip"`
7. Push karo:
   `git push origin arena/f1ba8616-all-vm-panel`
- GitHub login aapke apne account se hoga. Token ya password kisi ko chat mein na dein.
- 50 MiB se upar warning aayegi. Push phir bhi hoga, lekin repo bada hoga.

### 10.4 100 MB se badi file (Git LFS)
1. `git lfs install`
2. `git lfs track "*.zip"`
3. `git add .gitattributes`
4. Phir upar wale steps 5 se 7.
- Free plan par LFS ka storage aur bandwidth limit hota hai. Bahut baar upload karne par limit khatam ho sakti hai.

### 10.5 Google Drive folder (sabse aasaan, aapke liye)
- Ek folder banao, jaise `StarCloud Analyse Files`.
- Sab files upload karo (30 MB bhi chalegi).
- Folder ka naam ya link mujhe do. Main Google Drive connector se list karunga aur files padhunga.
- Note: Mpanel aur Nobita (Drive mein dikh rahi hain) par aapne drop kiya tha. Inhe main tab tak nahi kholunga jab tak aap na kahein.

## 11. Part 8 — Phone se Termux ke zariye file upload (easy steps)

> Ye steps aap khud apne phone par karoge. Assistant aapke GitHub login ya token ko nahi dekh sakta, isliye login aapke phone par hi hoga.

**Pehle ek baar setup**
1. Termux app install karo. F-Droid se lo (Play Store wala purana hai).
2. Termux kholo aur ye likho:
   `pkg update -y && pkg install -y git`
3. Phone ki storage ka access lo:
   `termux-setup-storage` (ek popup aayega, "Allow" dabao)
4. GitHub login: `pkg install -y gh` phir `gh auth login` chalao. Screen par diya gaya code browser mein daalo. Token ya password kisi ko mat dena.

**Har baar upload ke liye**
1. Repo lo:
   `git clone https://github.com/kingslayer76/All-vm-panel.git`
2. Folder mein jao aur branch badlo:
   `cd All-vm-panel` phir `git checkout arena/f1ba8616-all-vm-panel`
3. File copy karo. Maan lo file phone ke Downloads mein hai:
   `cp ~/storage/downloads/aapki-file.zip Analyse-File/`
4. Git ko apna naam aur email batao (sirf pehli baar):
   `git config user.name "Aapka Naam"` aur `git config user.email "aapka-github-email"`
5. Add, commit, push:
   `git add "Analyse-File/aapki-file.zip"`
   `git commit -m "Add aapki-file.zip"`
   `git push origin arena/f1ba8616-all-vm-panel`

**Badi file ke liye**
- 50 MB se upar warning aayegi, par push ho jayega.
- 100 MB se upar block hoga. Tab ye karo: `pkg install -y git-lfs`, phir `git lfs install`, phir `git lfs track "*.zip"`, phir `git add .gitattributes`, phir upar wale step 5 dohrao.

**Dhyan rakhne wali baatein**
- Sirf wahi files upload karo jo aap upload karna chahte ho. Personal data (database, log, password wali files) mat dalo.
- Upload ke baad GitHub par `Analyse-File/` folder mein file dikhegi.

*Part 8 khatam.*
